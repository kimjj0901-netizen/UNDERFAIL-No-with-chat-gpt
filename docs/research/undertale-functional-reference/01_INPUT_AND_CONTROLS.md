# 01 — 입력과 키 조작 체계

## 1. 입력을 먼저 분석해야 하는 이유

[설계 해석] Undertale이 강한 통일감을 주는 이유 중 하나는 탐험, 대화, 메뉴, 전투가 서로 완전히 다른 조작 방식을 요구하지 않는다는 점이다. 플레이어는 작은 입력 집합을 익히고, 게임은 현재 상태에 따라 그 입력의 의미를 바꾼다.

그 결과 플레이어는 “이번 화면에서는 어떤 버튼을 써야 하지?”를 매번 다시 배울 필요가 줄어든다. 조작법을 새로 배우는 부담이 줄어들면 텍스트, 적 캐릭터, 퍼즐, 공격 패턴에 집중할 수 있다.

## 2. PC 키 매핑의 증거 수준

### 2.1 이번 조사에서 확인된 것

| 액션 | 키 | 확인 수준 | 비고 |
|---|---|---|---|
| Confirm | Z 또는 Enter | [원작 게임 기능 — 2차 확인] | 메인 메뉴 설명이 PC 타이틀 진행 입력으로 Z/Enter를 명시한다. |
| Cancel | Shift | [원작 게임 기능 — 2차 확인] | SOUL 모드 설명은 CANCEL 또는 Shift를 누르고 있으면 빨간 SOUL 이동이 느려진다고 설명한다. |
| 방향 이동 | 방향키 | [원작 게임 기능 — 2차 확인] | 게임 플레이 및 2차 입력 설명에서 탐험·전투 방향 조작으로 반복 보고된다. PC 실제 실행으로 이번에 계측하지는 않았다. |
| Cancel | X | [검증 한계] | 커뮤니티 조작 설명에서 X로 기술되지만, 이번에 확인한 개발자 자료만으로 직접 교차 확인하지 못했다. |
| Menu | C 또는 Ctrl | [검증 한계] | 이전 답변에서 언급했으나 이번 조사에서 원출처나 직접 플레이로 충분히 교차 검증하지 못했다. 확정 매핑으로 사용하지 않는다. |
| Fullscreen | F4 | [검증 한계] | 이전 답변의 설명은 직접 검증하지 못했다. 이번 설계의 확정 조작에 포함하지 않는다. |
| Quit prompt | ESC | [검증 한계] | 이전 답변의 설명은 직접 검증하지 못했다. 브라우저 게임에서 ESC 의미를 복사하지 않는다. |

[중요] 이번 자료집은 “Z/Enter, X/Shift, C/Ctrl” 전체 표를 확정된 공식 키보드 명세로 선언하지 않는다. 확인 가능한 것은 Z/Enter의 타이틀 진행, Shift/CANCEL의 일부 기능 등이다. C/Ctrl과 X 키는 정식 PC 빌드 직접 확인 항목으로 남긴다.

### 2.2 컨트롤러와 PC 키보드를 분리해서 본다

Undertale 설정 페이지의 설명에 따르면 콘솔판에는 Confirm, Cancel, Menu 버튼을 재배치하는 설정이 있다. 콘솔 버튼 배치와 PC 키보드 고정 키 입력을 혼동해서는 안 된다.

PC용 키보드 리바인딩이 있는지 여부도 버전과 플랫폼에 따라 다를 수 있으므로, 공식 설정 화면 또는 실제 빌드에서 확인하기 전까지 단정하지 않는다.

## 3. 입력 액션과 실제 키를 분리하는 구조

[UNDERFAIL 제안] 내부 로직은 키 코드 자체를 직접 읽기보다 행동 단위의 입력 액션을 받는 구조가 적합하다.

~~~ts
type GameAction =
  | "UP"
  | "DOWN"
  | "LEFT"
  | "RIGHT"
  | "CONFIRM"
  | "CANCEL"
  | "MENU"
  | "INTERACT";

type InputContext =
  | "TITLE"
  | "OVERWORLD"
  | "DIALOGUE"
  | "CHOICE"
  | "BATTLE_MENU"
  | "SOUL_DODGE"
  | "PHONE"
  | "DISABLED";
~~~

이 구조의 핵심은 게임 로직이 Z나 Enter라는 키의 이름이 아니라 CONFIRM이라는 행동을 받는 것이다.

예를 들어 다음 매핑은 현재 프로젝트에 적용을 검토할 수 있는 제안이다.

| 행동 | 기본 키 후보 | 보조 키 후보 | 상태 |
|---|---|---|---|
| UP/DOWN/LEFT/RIGHT | 방향키 | WASD | [UNDERFAIL 제안] |
| CONFIRM | Z | Enter | [UNDERFAIL 제안] |
| CANCEL | X | Shift | [UNDERFAIL 제안] |
| MENU | C | Ctrl | [UNDERFAIL 제안, 원작 검증 필요] |
| INTERACT | CONFIRM 또는 별도 상호작용 액션 | E | [UNDERFAIL 결정 필요] |

권장 방향은 입력 체계를 하나로 통일하되, 기존 프로젝트의 Enter/Space/E 사용성을 한꺼번에 제거하지 않고 설정 또는 별칭으로 이행하는 것이다. Space를 유지할지, E를 조사 전용으로 유지할지는 사용자 승인 후 결정한다.

## 4. 입력 처리에서 반드시 분리할 이벤트

모든 키 입력을 단순한 “눌려 있음”으로만 처리하면 메뉴가 여러 번 이동하거나, Confirm이 여러 문장을 건너뛰거나, 한 프레임 안에서 서로 다른 씬이 같은 입력을 소비할 수 있다.

따라서 적어도 다음 세 종류를 구분해야 한다.

- JUST_PRESSED: 이번 프레임에 처음 눌림. 확인·취소·메뉴 선택에 사용.
- IS_DOWN: 누르고 있는 동안 유지. 이동, SOUL 이동, 일부 지속 동작에 사용.
- JUST_RELEASED: 이번 프레임에 놓임. 차지형 동작이나 키 반복 제어가 필요할 때 사용.

키보드 이동은 고정 반복 속도와 충돌 처리가 안정적이어야 한다. Confirm은 키를 누르고 있는 동안 동일 문장을 여러 번 진행시키지 않도록 입력 소비/잠금이 필요하다.

## 5. 입력 문맥 우선순위

하나의 입력이 두 개의 시스템에 동시에 전달되지 않도록 현재 활성 문맥이 우선권을 가져야 한다.

~~~text
DISABLED / TRANSITION
  └─ 입력 차단

TITLE
  └─ 타이틀 커서와 확인

DIALOGUE / CHOICE
  └─ 대화 진행 또는 선택지 커서
  └─ 탐험 이동은 잠금

BATTLE_MENU
  └─ 전투 명령 선택과 확정
  └─ 탐험 이동은 잠금

SOUL_DODGE
  └─ 전투 영역 안의 SOUL 이동만 허용

OVERWORLD
  └─ 방 이동과 조사 상호작용
~~~

## 6. 같은 키가 상태에 따라 다른 역할을 하는 방식

[설계 해석] 동일한 방향키는 타이틀의 선택 커서를 이동시키고, 대화 선택지를 이동시키고, 전투 메뉴를 이동시키며, 탐험 공간이나 SOUL을 움직일 수 있다. Confirm은 현재 화면에서 강조된 선택을 실행한다.

그렇다고 모든 문맥에서 모든 키를 똑같이 사용해야 한다는 뜻은 아니다. 예를 들어 탐험 중에는 조사 입력과 대화 입력을 분리할 수 있다. 핵심은 사용자가 규칙을 예측할 수 있게 하는 것이다.

## 7. 취소 키의 역할

Cancel은 메뉴에서 한 단계 뒤로 돌아가는 공통 규칙으로 설계할 수 있다.

~~~text
ACT 선택 목록 → 전투 명령 목록
아이템 목록 → 전투 명령 목록
전화 연락처 → 전화 메인 화면
대화 선택지 → 허용된 취소/이전 상태
~~~

[검증 필요] Undertale PC판에서 X/Shift가 모든 메뉴·대화 맥락에서 동일한 종료 규칙을 갖는지, 대화 속도와 별도 동작이 어떤 키에 연결되는지는 직접 실행으로 세부 확인해야 한다.

## 8. UNDERFAIL에 적용할 테스트

| 테스트 ID | 테스트 | 합격 조건 |
|---|---|---|
| INPUT-01 | 타이틀에서 방향키 | 포커스가 한 항목씩 이동한다. |
| INPUT-02 | 타이틀 Confirm | Z와 Enter 별칭이 동일한 진입을 실행한다. |
| INPUT-03 | 대화 중 이동키 | 주인공이 이동하지 않는다. |
| INPUT-04 | 대화 Confirm | 입력 한 번당 허용된 페이지 하나만 진행한다. |
| INPUT-05 | ACT 메뉴 Cancel | 한 단계 이전 메뉴로 돌아간다. |
| INPUT-06 | 적 턴 중 탐험 입력 | 탐험 씬 입력을 소비하지 않는다. |
| INPUT-07 | SOUL_DODGE 중 메뉴키 | 지정하지 않은 상태에서는 메뉴를 열지 않는다. |
| INPUT-08 | 씬 전환 중 연속키 | 이전 씬과 다음 씬이 같은 입력을 중복 소비하지 않는다. |
| INPUT-09 | 키보드 별칭 동시 입력 | Z와 Enter를 동시에 누르는 등 별칭 중복 입력이 이중 실행되지 않는다. |
| INPUT-10 | 브라우저 기본 단축키 | 게임이 허용한 키만 예방적으로 기본 브라우저 동작을 차단하고, 일반 접근성 입력을 과도하게 막지 않는다. |

## 9. 직접 확인해야 할 미해결 사항

- PC 배포 빌드에서 실제 메뉴 키가 무엇인지.
- X와 Shift의 동작이 모든 PC 빌드에서 동일한지.
- 취소 입력이 대화 텍스트 속도에 어떤 영향을 주는지.
- 키보드 재설정 가능 여부와 플랫폼별 차이.
- 방향키 두 개를 동시에 눌렀을 때 대각선 이동이 허용되는지.
- 키를 놓았을 때 즉시 멈추는지, 가속/감속이 있는지.
- 게임이 창 모드/전체 화면에서 입력을 어떻게 처리하는지.

이 항목은 현재 추측으로 채우지 않는다.
