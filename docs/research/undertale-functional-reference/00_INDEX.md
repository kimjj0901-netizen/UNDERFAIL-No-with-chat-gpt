## 1. 태그 규칙

모든 문서에서 다음 태그를 사용한다.

- [원작 개발자 발언]: Toby Fox 본인이 직접 설명한 개발 의도 또는 제작 과정.
- [원작 게임 기능 — 2차 확인]: 게임 위키 등 커뮤니티 문서가 설명하는 플레이 기능. 게임 파일 직접 검증과 동일하지 않다.
- [공개 데모 코드]: 공개된 Undertale Demo의 GML 소스 범위에서 확인 가능한 정보. 정식판 전체 코드라고 간주하지 않는다.
- [직접 관찰 필요]: 실제 게임을 재생하며 확인해야 하지만 이번 조사에서 직접 플레이를 수행하지 않은 항목.
- [설계 해석]: 확인된 플레이 특징을 기획 관점에서 해석한 내용.
- [UNDERFAIL 제안]: 사용자 승인 전까지 정사가 아닌 개발 제안.
- [기존 프로젝트 사실]: 현재 UNDERFAIL 저장소 문서 또는 저장소 트리에서 확인한 사실.
- [미정/보류]: 사용자가 결정하지 않았거나 명시적으로 보류한 사항.
- [검증 한계]: 접근 가능한 증거만으로 확정할 수 없는 사항.

## 2. 반드시 지켜야 하는 구분

1. Undertale의 기능을 확인한 사실과 UNDERFAIL에 적용하자는 제안을 같은 문장으로 섞지 않는다.
2. 제안된 수치·키 매핑·해상도·상태 변수는 사용자가 승인하기 전까지 정사 또는 구현 요구사항으로 승격하지 않는다.
3. 원작의 대사 전문, 캐릭터 스프라이트, 배경, UI 아트, 음악, 고유 공격 패턴을 복사하지 않는다. 이 자료집은 기능·구조·시각적 원리를 분석한다.
4. 공개 Demo GML은 정식판 전체 코드가 아니다.
5. 위키 문서는 세부 수치와 내부 구조를 찾는 데 유용하지만 Toby Fox 공식 사양서로 취급하지 않는다.
6. 이번 작업은 문서 자료집 작성이다. 실제 게임 코드와 현재 에셋을 수정하거나 교체하지 않았다.
7. 기존 창작 원본인 CREATIVE_DECISION_WORKBOOK.md와 스토리 인덱스 0~1.7은 변경하지 않는다.

## 3. 자료집 전체의 가장 중요한 설계 문제

Undertale 특유의 체감은 픽셀 그래픽이나 전투 박스 한 개로 생기지 않는다. 다음이 동일한 입력 언어와 진행 리듬을 공유하면서 결합된다.

~~~text
입력
  ├─ 탐험 이동
  ├─ 조사 / 대화
  ├─ 타이틀 / 메뉴
  └─ 전투 명령 / SOUL 회피
       ↓
상태 전환
       ↓
텍스트·시각·음향 피드백
       ↓
세계·캐릭터·분기 상태 변화
       ↓
다음 방 / 다음 조우
~~~

따라서 UNDERFAIL도 UI 모양만 바꾸기보다 입력 시스템, 대화 진행, 방의 리듬, 전투 상태, ACT 결과, 캐릭터 반응이 일관된 규칙으로 연결되는지를 먼저 확인해야 한다.

## 4. 연구 경계

- 정식판의 모든 내부 함수명·모든 변수·모든 프레임 수를 완전히 확보했다고 주장하지 않는다.
- 원작 게임을 이 환경에서 직접 실행하지 않았다.
- 일부 수치는 공개 게임 위키의 정리값이며, 원본 런타임 디컴파일로 교차 검증하지 않았다.
- 640×480은 위키가 창 모드 스크린샷을 표현하는 기준으로 설명한다. 이를 곧바로 게임 내부 논리 해상도나 UNDERFAIL의 필수 해상도로 일반화하지 않는다.
- 컨트롤러·콘솔·Linux·PC 버전의 조작 차이를 모두 동일한 값으로 취급하지 않는다.

## 5. 현재 UNDERFAIL 자료 기준

저장소 문서에서 확인한 핵심 기준은 다음과 같다.

- 프로젝트 스택: Phaser 4.2.1 + TypeScript + Vite.
- 기술 설계 문서가 기록한 논리 해상도: 960×540.
- 기술 설계 문서의 입력 초안: 방향키/WASD 이동, Enter/Space 확인·상호작용, 방향키 메뉴 이동, Escape 취소 또는 메뉴 닫기.
- 기술 설계 문서가 적은 탐험 상호작용 키: E.
- 현재 Scene 트리에는 TitleScene, NameEntryScene, PrologueScene, RoomScene, WelfareCorridorScene, RegularEncounterScene, NerdstablookEncounterScene 등을 포함한다.
- 현재 별도 InputManager 전용 파일이 파일 트리에 나타나지 않는다. 코드 내부에 유사 기능이 전혀 없다고 단정한 것은 아니며, 소스 전체 감사는 별도 작업이다.

상세 비교는 12번 파일에서 다룬다.
