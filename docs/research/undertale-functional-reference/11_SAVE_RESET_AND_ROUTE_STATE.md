# 11 — SAVE, LOAD, RESET, True Reset과 세계 상태

## 1. 저장 기능과 세계관 기능

Undertale의 SAVE는 단순히 진행 상황을 파일에 쓰는 UI만이 아니라, 세계관 안에서 특정 인물이 세계의 상태를 저장/불러오는 능력으로 해석된다.

[원작 게임 기능 — 2차 확인] 게임에는 하나의 일반 SAVE 슬롯이 있으며, SAVE 포인트와 자동 저장이 해당 상태를 덮어쓰는 것으로 정리되어 있다. 주인공 HP가 0이 되면 가장 최근 SAVE/자동 저장 상태로 돌아간다는 설명도 있다.

## 2. Load / Reset

- Load: 가장 최근 저장 상태를 불러온다.
- Reset: 진행을 처음부터 다시 시작하며, 많은 상태를 지우지만 이름 등 일부 정보는 남을 수 있다고 설명된다.
- True Reset: 특정 엔딩 이후 사용할 수 있는 별도 리셋으로, 일반 Reset과 구분된다.
- 특정 루트 완료 후 별도 상태 플래그가 남는 것으로 정리되어 있다.

이 요약은 위키의 시스템 설명에 근거한다. 모든 변수의 정확한 파일 저장 방식이나 플랫폼 예외를 이 자료가 전부 설명하지는 않는다.

## 3. SAVE의 서사적 의미

[설계 해석] 저장 기능과 캐릭터의 기억이 연결되면, 게임은 플레이어의 반복 행동을 세계관의 일부로 표현할 수 있다. 일부 인물이 이전 행동을 기억하거나 익숙함을 표현하는 것은 플레이어가 단순히 파일을 되돌렸다는 사실을 이야기 속 경험으로 바꾸는 방식이다.

## 4. UNDERFAIL에서 보류해야 하는 이유

[기존 프로젝트 사실] UNDERFAIL 창작 문서와 마스터 프롬프트는 다음을 미정/보류로 둔다.

- 저장·불러오기·재시작을 인물들이 인식하는가.
- HP 0이 세계관에서 어떤 의미인가.
- 몰살에 해당하는 루트의 조건과 정확한 명칭.
- 지역별 처치 카운터나 제압 기록.
- 사망/제압 이후의 결과와 후속 대사.

따라서 Undertale의 SAVE/RESET 의미를 그대로 옮기지 않는다. 원작에서 핵심 기능이라는 이유만으로 UNDERFAIL의 정사가 되지 않는다.

## 5. 기술 저장과 서사 저장을 분리하는 방안

[UNDERFAIL 제안] 기획이 결정되기 전까지 게임은 일반 세션 저장 또는 기술 테스트용 임시 저장을 사용하더라도, 세계관 캐릭터가 기억하는 설정을 만들지 않는다.

~~~ts
interface TechnicalSaveData {
  schemaVersion: number;
  currentRoomId: string;
  playerPosition: { x: number; y: number };
  currentHp: number;
  inventoryIds: string[];
  storyFlags: Record<string, boolean | number | string>;
}

interface NarrativeMemoryState {
  enabled: boolean;
  memoryFlags: string[];
}
~~~

NarrativeMemoryState는 사용자가 세계관적 기억 시스템을 승인하기 전까지 활성화하지 않는다.

## 6. 플래그 설계

게임 진행의 기본 플래그는 세부 전투 카운터와 분리하는 것이 좋다.

- Story flags: 특정 사건을 완료했는지.
- Encounter flags: 특정 조우에서 어떤 결과가 났는지.
- Relationship flags: 인물별 관계 상태.
- Discovery flags: 사물/비밀을 발견했는지.
- Route flags: 특정 이야기 경로의 진행 상태.

[미정/보류] UNDERFAIL의 최종 플래그 수, 루트 조건, 저장 방식은 확정되어 있지 않다.

## 7. SAVE Point를 복제하지 않고 기능을 참고하기

[설계 해석] 특정 공간/사물을 저장의 시각적 상징으로 만드는 것은 기능적 참고가 가능하다. 하지만 별도의 저장 기믹을 만들 때 이름, 외형, 대사, 세계관 해석을 그대로 옮기지 않는다.

## 8. 구현 전 결정해야 할 것

1. 웹 브라우저에서 저장을 어떤 기술로 할 것인지.
2. 세션 상태와 영속 저장 상태를 구분할 것인지.
3. 리셋 후에도 유지하는 데이터가 있는지.
4. 캐릭터가 이전 회차를 인식하는지.
5. HP 0 이후에 어떤 장면으로 이동하는지.
6. 플레이어가 수동 저장/자동 저장을 사용할지.
7. 저장 기능이 작품 주제인 선택권과 어떤 관계를 갖는지.

이 결정이 이루어질 때까지 원작의 저장 파일 구조와 루트 카운터를 구현 요구사항으로 복사하지 않는다.
