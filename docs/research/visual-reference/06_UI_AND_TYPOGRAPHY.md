# 06 — UI와 타이포그래피

## 1. 일관된 UI 언어
UI의 일관성은 모든 화면을 똑같이 꾸미는 뜻이 아니다. 동일한 역할의 요소가 비슷한 위치·여백·외곽선·선택 반응·입력 규칙을 공유해야 한다.

## 2. UI 종류
- 타이틀 시작 항목.
- 이름 입력.
- 컷신 대화판.
- 탐험 중 조사 프롬프트.
- 일반 대화창.
- 선택지.
- 전투 명령.
- ACT 하위 메뉴.
- ITEM 하위 메뉴.
- MERCY 상태.
- HP/상태 정보.
- 일시정지/설정(아직 전체 메뉴는 미구현).

## 3. 현재 UI의 차이
현재 화면은 대체로 짙은 남청·청록 패널, muted gold 외곽선, 따뜻한 종이색 텍스트를 사용한다. 일부 화면은 둥근 패널, 일부는 사각 패널을 사용하며, 메뉴 글꼴과 텍스트 크기도 Scene별로 다르다.

[제안] 색상은 기존 톤을 기본으로 유지하고, 패널 모서리, 선 두께, 텍스트 계층, 명령 선택 상태, 키 안내의 규칙을 통일한다. 전투와 오프닝은 화면 목적이 다르므로 동일 패널 크기를 강요하지 않는다.

## 4. 타이포그래피 규칙
- 한 화면의 제목은 본문보다 확실히 큰 크기.
- 화자명과 대사 본문을 구분.
- 키 안내는 실제 조작과 일치.
- 한국어 글리프에서 잘림/줄바꿈을 확인.
- 작은 화면에서 10~12px 수준의 안내문은 확대 배율에 따라 읽기 어려울 수 있으므로 실기 점검.
- 중요한 상태를 색상만으로 전달하지 않는다.

## 5. 입력 안내
이번 브랜치의 통일 입력 기본안:
- Confirm: Z / Enter / Space
- Cancel: X / Shift / Escape
- Move/select: 방향키 / WASD
- Interact: E 및 Confirm 별칭
- Phone: C
- C/Ctrl Menu: 예약된 액션으로 정의했지만, 실제 메뉴 화면은 아직 구현되지 않았으므로 메뉴 조작이 작동한다고 안내하지 않는다.

## 6. 검증
- 키 안내 문구와 실제 입력이 일치하는가?
- 키보드만으로 모든 핵심 메뉴를 사용할 수 있는가?
- 클릭 가능한 UI는 키보드로도 접근 가능한가?
- 비활성 메뉴와 사용 가능한 메뉴가 구분되는가?
- 대화창과 전투 패널이 화면 요소를 가리지 않는가?
- 한국어 폰트 fallback이 정상인가?

## 7. Recognition rather than recall — 기억보다 인식
SUPERJUMP의 UX 분석은 Undertale의 메뉴와 적별 상호작용을 “회상”보다 “인식”을 돕는 방식으로 설명한다. 플레이어가 가능한 행동을 매번 기억해서 떠올리는 대신, 현재 상대와 상황에 맞는 선택지를 보고 판단할 수 있게 한다.

UNDERFAIL 적용 제안:
- 키 안내는 플레이어가 현재 상태에서 사용할 수 있는 입력과 일치해야 한다.
- 선택지와 명령은 현재 대상에게 가능한 행동만 보여 주거나, 사용 불가 이유를 표현한다.
- 전투 화면의 적/대사/보드/명령은 서로 모순되지 않아야 한다.
- 조사할 수 있는 오브젝트는 접근 가능할 때 프롬프트가 떠서 발견 가능성과 조작 방식을 동시에 알려준다.
- 조작이 바뀌는 특수 전투에서는 새로운 규칙을 글 한 줄만으로 숨기지 말고 시각 변화와 함께 설명한다.

## 8. 전투 화면을 네 층으로 이해하기
분석자는 화면을 대략 다음의 네 계층으로 설명한다.
1. 캐릭터/적의 표현 공간.
2. 상황·반응 텍스트 영역.
3. HP·LV 등 상태 정보.
4. FIGHT/ACT/ITEM/MERCY 명령 영역.

UNDERFAIL의 전투 UI도 이 계층을 참고하되, 화면의 고유 비율·그래픽·아이콘을 복사하지 않는다.
