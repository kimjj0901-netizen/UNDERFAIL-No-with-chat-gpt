# 03 — 탐험 화면과 방 디자인

## 1. 분석 대상
- 방의 바닥/벽/장식.
- 이동 경로와 조사 오브젝트.
- 캐릭터와 오브젝트의 시선 관계.
- 출입구 위치.
- 플레이어의 시작 위치.
- 방 안의 주요 동선.
- 텍스트 UI가 맵을 가리는 정도.
- 방에서 다음 방으로 이어지는 출구 피드백.

## 2. 이미지 참조
대표 화면은 MobyGames Undertale Windows screenshot gallery에서 확인한다.
https://www.mobygames.com/game/74938/undertale/screenshots/windows/

스크린샷만으로는 정확한 콜라이더나 카메라 알고리즘이 확인되지 않는다. 공간 기능과 시각적 배치는 구분해 분석한다.

## 3. UNDERFAIL 현재 상태
- 논리 해상도 960×540.
- 교육복지실과 복도 배경은 960×540 SVG.
- Player/NPC는 개별 SVG를 사용.
- RoomScene과 WelfareCorridorScene은 각각 좌표·충돌·조사 타겟을 관리한다.
- 화면 하단의 안내 문구가 이동/조사 방법을 설명한다.

## 4. 우선 개선 원칙
- [제안] 조사 가능한 오브젝트는 배경 장식과 명확히 구분하되, 상호작용 표시가 화면을 지나치게 가리지 않게 한다.
- [제안] 길은 시각적 대비와 오브젝트 배치로 자연스럽게 읽히게 한다.
- [제안] NPC 이름표가 캐릭터 머리나 대화 UI와 겹치지 않게 한다.
- [제안] 복도·교실의 바닥 무늬는 공간 방향을 전달하는 데 쓰되, 플레이어 캐릭터의 식별을 방해하지 않는다.
- [제안] 조사 반경, 충돌 상자, 시각적 오브젝트 bounds를 별도 데이터로 유지한다.
- [제안] 같은 방 재방문 시 이전 행동을 반영한 소품/대사 변화가 있는지 검토한다.

## 5. 960×540 대 4:3
MobyGames 이미지의 640×480은 해당 스크린샷의 표시 크기다. 이것만으로 Undertale 엔진 내부 논리 해상도가 640×480이라고 단정하지 않는다. UNDERFAIL은 현재 960×540 및 이를 전제로 한 자산을 사용하므로 4:3으로 즉시 바꾸지 않는다.

비교 프로토타입에서는:
- 동일한 방을 두 비율로 배치.
- 텍스트 폭과 줄 수 비교.
- 캐릭터 크기/시인성 비교.
- 전투 메뉴와 회피 영역 비교.
- 브라우저 창에서 FIT 여백 및 가독성 비교.

## 6. 플레이테스트 체크
- 벽 모서리에 끼이지 않는가?
- 가구와 NPC를 통과하지 않는가?
- 상호작용 거리가 직관적인가?
- 근접 오브젝트가 여러 개일 때 대상이 예측 가능한가?
- 출구가 조사 가능한 상태인지 분명한가?
- 화면 하단 안내가 캐릭터나 출구를 가리지 않는가?

## 7. 추가 레벨 디자인 분석 — 경로의 직관성
Game Developer의 “The Hidden Level Design of Undertale”은 분석자 Sinden Enter의 개인적 견해로서, 초반 지역은 오른쪽 방향 진행이 익숙하게 느껴지며, 이후 일부 지역은 위쪽 이동 비중이 높아져 여정의 마무리 감각을 강화한다고 해석한다. 이는 제작자 공식 설명이 아니라 [2차 분석/개인 해석]이다.

UNDERFAIL 적용 제안:
- [제안] 각 방의 다음 출구가 처음부터 너무 노골적이지 않더라도, 주요 조명·바닥 선·가구 방향·NPC 시선으로 이동 흐름을 읽을 수 있게 한다.
- [제안] 주요 길과 비밀 경로는 색상만이 아니라 폭·모양·장식·환경 변화로 구분한다.
- [제안] 지역의 진행 방향은 학교 공간의 논리(복도, 계단, 교실 배치)를 바탕으로 정한다. 원작의 오른쪽/위쪽 진행 패턴을 강제로 복사하지 않는다.
- [제안] 보조 경로가 주요 스토리 흐름에서 플레이어를 지나치게 멀리 빼내지 않도록 landmark와 재진입 지점을 둔다.

출처: https://www.gamedeveloper.com/design/the-hidden-level-design-of-undertale

## 8. 상호작용 가시성과 기억 부담
SUPERJUMP의 Undertale UX 분석은 플레이어가 가능한 행동을 기억에서 꺼내도록 강요하기보다, 적의 상태와 맥락 속에서 가능한 행동을 인식하도록 돕는 점을 강조한다. 이는 [2차 UX 분석]이다.

UNDERFAIL 적용:
- 상호작용 프롬프트는 대상과 가까워졌을 때만 보인다.
- 대상이 조사 가능한 상태인지 아닌지 명확하게 표현한다.
- 퍼즐에서 이미 알려 준 규칙은 필요한 순간에 단서 형태로 다시 인식할 수 있게 한다.
- 메뉴에서 비활성 명령을 숨기거나 흐리게만 하지 말고, 필요하다면 이유를 짧게 알려준다.

출처: https://www.superjumpmagazine.com/applying-usability-heuristics-to-undertale/
