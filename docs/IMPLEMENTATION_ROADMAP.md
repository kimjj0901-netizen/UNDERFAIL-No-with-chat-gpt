# UNDERFAIL 구현 로드맵

## 현재 상태

현재 저장소에는 게임 코드와 패키지 설정이 없으며, 기획 문서 기반을 구축하는 단계다. 아래 순서는 문서 승인과 핵심 창작 결정 이후 실행한다.

조사와 첫 대본 초안은 [RESEARCH_AND_DESIGN_NOTES.md](RESEARCH_AND_DESIGN_NOTES.md), [UNDERFAIL_STORY_SUPPLEMENT_RESEARCH.md](UNDERFAIL_STORY_SUPPLEMENT_RESEARCH.md), [SCRIPT_BIBLE.md](SCRIPT_BIBLE.md)에 기록한다. 이 단계의 콘텐츠는 모두 Proposal이다.

## 단계

### 1. 기획 기준선 확정

- 정사·제안 목록을 사용자와 검토한다.
- 학교명, 전투 세계관, 주인공 표현, 핵심 인물의 이름과 동기를 승인한다.
- 스토리 문서의 장별 목표·분기·복선을 하나의 추적표로 통합한다.
- 조사 노트의 적용 원칙과 프롤로그 대본 바이블을 검토한다.

### 2. 기술 스파이크

- TypeScript/Vite/Phaser 후보를 최소 화면으로 검증한다.
- 키보드 입력, 해상도 대응, 장면 전환, 저장소 접근을 확인한다.
- 프레임 드롭과 모바일/키보드 접근성 요구를 기록한다.

### 3. 수직 슬라이스

- 프롤로그부터 첫 대응 심사까지 구현한다.
- 이동·충돌·상호작용·대화·한 보스 전투·저장/불러오기를 연결한다.
- 평화 해결과 강제 제압 두 결과를 재방문에서 확인한다.

### 4. 콘텐츠 확장

- 지역을 순서대로 추가하고, 스토리 데이터와 실행 로직을 분리한다.
- 보스마다 공격 패턴, 평화 조건, 패배 결과, 재등장 대사를 테스트한다.
- 플래그 스키마와 저장 버전 마이그레이션을 유지한다.

### 5. 루트·엔딩 구현

- 공통 변수와 관계 상태를 타입으로 정의한다.
- 연결/부분 합격/완벽한 답안/빈 페이지 루트를 독립 테스트한다.
- 최종 지원 매트릭스와 누락 인물 조건을 자동 검증한다.

### 6. 품질·배포

- 타입 검사, 린트, 단위 테스트, 브라우저 스모크 테스트를 CI에 연결한다.
- 키보드 조작, 색 대비, 텍스트 속도, 저장 실패 안내를 점검한다.
- Vite 정적 빌드 결과를 GitHub Pages 등 호스팅 후보에 배포한다.

## 제안 데이터 경계

```text
src/
  data/        승인된 대사·인물·보스·플래그 데이터
  scenes/      Phaser 장면과 화면 흐름
  systems/     대화·전투·관계·저장 시스템
  state/       타입이 있는 게임 상태와 루트 판정
  ui/          메뉴·대화창·접근성 설정
tests/         시스템 및 루트 테스트
```

실제 디렉터리와 패키지는 기술 스파이크 후 확정한다.

## 완료 기준

- 처음부터 엔딩까지 중단 없이 진행 가능하다.
- 각 루트가 독립적으로 재현되고, 저장/불러오기가 플래그를 보존한다.
- 평화적 해결이 단순한 보상 선택이 아니라 최종 사건과 연결된다.
- 문서의 승인 상태와 구현 콘텐츠가 일치한다.
