# 전투 시스템 설계 명세 — 1차

상태: 공통 전투 규칙은 설계 제안 단계. 2026-11-27 기준 rhythmMote 일반 조우에 한정한 첫 수직 단면이 구현되었으며, 다른 전투 Scene의 공통화는 미완료.

## 1. 전투의 정체성
전투는 캐릭터의 목표와 플레이어의 선택이 충돌하는 상황이다. UNDERFAIL 정사에서 전투는 현실적인 살해 행위가 아니라 학생과 교직원이 각자의 목표를 두고 벌이는 경쟁·대립이다.

## 2. 공통 전투 단계
- INTRO
- PLAYER_COMMAND
- PLAYER_SUBMENU
- ACTION_RESOLUTION
- ENEMY_TURN_SETUP
- SOUL_DODGE
- HIT_RESOLUTION
- END_CHECK
- RESOLVED

## 3. 명령의 역할
- FIGHT: 타이밍 기반 대응/공격. 상대와 장비에 맞춘 표현.
- ACT: 캐릭터별 행동. 태도·대화·패턴·해결 조건에 영향.
- ITEM: 보유 물건과 대상에 따른 사용.
- MERCY: 비폭력 해결 또는 허용된 이탈.

## 4. ACT 설계 규칙
각 ACT에는 다음을 기록한다.
- 사용 가능 조건.
- 첫 반응.
- 반복 반응.
- 바뀌는 캐릭터 상태.
- 바뀌는 공격/회피 규칙.
- Mercy 가능 여부.
- 다음에 조사할 수 있는 단서.
모든 ACT가 전부 상태를 바꾸는 것은 아니다. 어떤 ACT는 정보를 전달하는 용도일 수 있다.

## 5. 공격 패턴
패턴은 다음을 정의한다.
- 지속 시간.
- SOUL 모드.
- 회피 영역.
- 예고 신호.
- 등장/이동/소멸.
- 충돌 및 피해 판정.
- 완료 조건.
- 난이도 단계.
패턴은 원작의 형태를 복제하지 않고 학교·규칙·리듬·종이·빛 등 UNDERFAIL 고유 상징으로 제작한다.

## 6. 해결과 HP 0
HP 0 이후의 세계관 결과는 [미정/보류]. 코드가 편하다는 이유로 사망이나 제압을 확정하지 않는다. 기존 프로토타입의 후퇴/평화 해결은 임시 결과로 기록한다.

## 7. 게임성 기준
- 예고를 보고 학습할 수 있어야 한다.
- 맞았을 때 무엇에 맞았는지 이해할 수 있어야 한다.
- 쉬운 패턴 뒤에는 새로운 조합을 제시한다.
- 같은 패턴만 속도를 올려 반복하지 않는다.
- 전투는 스토리상 이유가 있어야 한다.
- 조우 빈도는 탐험과 캐릭터 관계 장면을 끊지 않아야 한다.


## 8. 2026-11-27 첫 수직 단면 구현 상태

- 구현 Scene: RegularEncounterScene. 대상 조우: rhythmMote(박자 먼지).
- 공통으로 분리한 책임: 전투 상태 전이 검증, 고정 스텝 실행, 리듬 타이밍 판정.
- FIGHT: 네 박자 중 세 짧은 간격 뒤 긴 간격에 맞춰 Confirm한다. 판정은 precise / steady / miss로 나뉘며, 결과가 다음 패턴의 발사 간격에 반영된다.
- ACT watch: 세 짧은 빛과 한 긴 빛이라는 패턴 정보를 알려 주고, 이후 FIGHT 판정 창을 넓힌다.
- 회피 패턴도 300ms / 300ms / 300ms / 900ms 간격을 사용한다. 관찰 정보와 실제 행동의 규칙이 일치하도록 유지한다.
- 공격 예고와 반응 단계를 추가했다. 회피 중 실제 프레임 delta가 아니라 동일한 고정 시뮬레이션 스텝으로 이동·패턴 시계·충돌을 계산한다.
- HP 0, 사망/제압, SAVE/RESET, 루트 카운터 규칙은 변경하지 않는다.
- 이 구현은 전체 전투 시스템 완성이나 모든 전투 Scene의 공통화 완료를 뜻하지 않는다. 실제 브라우저 플레이 및 밸런스 QA도 미실행이다.
